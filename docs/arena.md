# Арена: комнаты и вызовы

Арена использует единую базовую v1. Комнаты и предложения принадлежат домену
`battles`. Список доступных комнат восстанавливается через REST; он содержит
ожидающие комнаты, создатель которых сейчас не участвует в активном бою.
Активные и завершённые бои доступны по прямой ссылке, собственный активный
бой — также через состояние арены. Созданная дуэль сразу доступна в списке;
клиент обновляет список каждые 5 секунд и по кнопке.

## Дуэль

1. Игрок создаёт комнату `duel` с названием и настройками поля. Единственный
   начальный участник — владелец комнаты, команда 0.
2. Другой игрок просматривает комнаты и бросает вызов. Предложение не добавляет
   бойца в комнату и не резервирует персонажа. Можно одновременно вызвать
   нескольких владельцев комнат; владелец может получать несколько вызовов.
   Повтор отправки в ту же комнату возвращает существующий ожидающий вызов.
3. Владелец получает уведомление с именем соперника и названием комнаты на любом
   экране игры. Он может принять или отклонить вызов. Отправитель видит ожидающие
   ответы в лобби и может отозвать любое предложение.
4. Первый успешно принятый вызов немедленно запускает бой в комнате получателя.
   Отдельного подтверждения старта нет. Сервер заново проверяет отсутствие
   активного боя у обоих героев и фиксирует актуальные характеристики, навыки,
   экипировку, рюкзак, жеребьёвку и срок хода обычным сценарием старта.
5. В той же транзакции принятый вызов получает `accepted`, а все остальные
   ожидающие входящие и исходящие предложения обоих героев — `cancelled`.
   Они исчезают у остальных адресатов. При одновременном принятии разных
   предложений одного героя только одна транзакция может запустить бой;
   другая получает 409 и перечитывает состояние.

Собственный вызов запрещён. Принять предложение может только получатель;
отклонить — получатель, отозвать — отправитель. Аккаунт должен владеть указанным
персонажем. Уже обработанное предложение нельзя принять повторно. Повторный
отказ или отзыв безопасен и не меняет результат принятого боя.
Нельзя вызвать занятого героя или отправить вызов из активного боя.

Начало любого другого режима также сбрасывает предложения его участников.
Оставшиеся ожидающие комнаты занятого создателя скрываются до конца его боя;
после завершения они снова доступны, прежние предложения не восстанавливаются.
Сценарии вступления в команды, боя с ботом и подземелья сохраняются. Для дуэли
прямые `join` и `start` недоступны: требуется принятие вызова.

## Уведомления и восстановление

Состояние выбранного героя `ArenaState` содержит `incoming`, `outgoing` и
`activeBattleId`. Оно читается через REST каждые 3 секунды на любом игровом
экране и после действий. Получатель после успешного принятия сразу переходит
в бой. Отправитель должен автоматически попасть в тот же бой при первом
получении его `activeBattleId`; дополнительное нажатие не требуется.
При возврате фокуса окну или видимости вкладке состояние перечитывается сразу,
чтобы ограничения фоновых таймеров браузера не задерживали переход.
Перезагрузка или повторный вход выбранным героем восстанавливает текущий бой.
Автоматический переход выполняется один раз для каждого боя за время работы
экрана выбранного персонажа. Если игрок затем сам открыл другой раздел,
следующие опросы не должны возвращать его принудительно: остаётся кнопка
«Перейти в бой». Новые WS-события,
браузерные уведомления и фоновая очередь для арены не используются.

## REST API

Все пути начинаются с `/api/v1`.

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/battles` | Доступные ожидающие комнаты |
| GET | `/battles/arena/:characterId` | Собственные предложения и активный бой |
| POST | `/battles/:id/challenges` | Отправить `{characterId}`; вернуть `ArenaChallenge` |
| POST | `/battles/:id/challenges/:challengeId/accept` | Принять `{characterId}`; вернуть снимок начатого боя |
| POST | `/battles/:id/challenges/:challengeId/dismiss` | Отклонить или отозвать `{characterId}`; вернуть `{ok: true}` |

`ArenaChallenge` хранит ID вызова, комнаты, отправителя и получателя, имена
для уведомления, время создания и статус `pending/accepted/declined/cancelled`.
Принятие не требует `Battle.version` из списка: предложение проверяется под
серверной блокировкой. Успешный старт увеличивает обычный счётчик версии боя.

Серверные проверки: `test:infrastructure` покрывает видимость комнаты,
несколько предложений, дубликат отправки, полномочия получателя, гонку принятия,
откат ошибки сохранения, отзыв, отказ и отмену при старте другого режима.
Браузерная проверка `test:ui` покрывает отправку нескольких вызовов,
уведомление вне арены, отказ, принятие и мобильную ширину. Отдельный сценарий
с двумя независимыми аккаунтами проверяет автоматический вход обоих игроков,
восстановление после перезагрузки, обновление при фокусе и добровольный выход
с экрана боя при недоступном WS. Для второго браузера Firefox:
`pnpm --filter @game/web exec playwright install firefox`, затем
`ARENA_TEST_FIREFOX=1 pnpm --filter @game/web test:ui`.
