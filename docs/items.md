# Предметы и расширяемые группы

Определение (`ItemDefinition`) хранится в MongoDB `items`: `id`, название,
описание, `groupId`, `stackLimit` и параметры поведения. Конкретный предмет или
стэк (`ItemInstance`) хранится в PostgreSQL: собственный UUID, `itemId`, владелец,
инвентарь либо `null`, количество и слот экипировки либо `null`.

Удаление экземпляра не удаляет описание из каталога. Определение, на которое
ссылаются существующие предметы, нельзя физически убирать из каталога до
миграции этих экземпляров. Старые определения лечебных предметов получают
группу `potions` и лимит стэка 99 без перезаписи названий, описаний и лечения.
Снижение лимита стэка требует предварительной миграции существующих стэков.

## Группы и действия

Группы — документы MongoDB `itemGroups`, а не фиксированный enum категорий.
Документ содержит `id`, `name`, `description`, `actions`. Новая группа с уже
поддержанными действиями добавляется данными; сервер и клиент не требуют
нового `switch` по категории. В интерфейсе фильтры строятся из этого каталога.

| Группа | Дополнительные операции | Параметры определения |
| --- | --- | --- |
| `weapons` — оружие | Экипировать, снять | `equipSlot`, `bonuses`; стэк строго 1 |
| `equipment` — экипировка | Экипировать, снять | `equipSlot`, `bonuses`; стэк строго 1 |
| `potions` — зелья | Применить в бою, разделить/объединить стэк | `heal`, `stackLimit` |
| `resources` — ресурсы | Разделить/объединить стэк | `stackLimit` |
| `scrolls` — свитки | Прочитать, разделить/объединить стэк | `grantedSkillId`, `stackLimit` |

Поддержанные действия зарегистрированы в `itemActionIds`, названия — в
`itemActionNames`, обработчики — в ядре инвентаря. Для нового поведения нужно
добавить идентификатор, обработчик, проверку доступности, UI для его параметров
и тесты. Нельзя объявлять в каталоге действие, для которого нет обработчика.
Общие операции с принадлежностью описаны в [инвентаре](inventory.md).

Начальный каталог: зелье здоровья, железный меч (+3 атаки), кожаная броня
(+2 защиты, +10 максимального HP), железная руда, лечебная трава и свиток Искры.
Новый персонаж получает 3 зелья, меч, броню, 8 руды и один свиток. Старым героям
новые предметы автоматически не начисляются; их существующее имущество сохраняется.

## Поведение групп

Экипировка допустима только из основного рюкзака. Слот определяется предметом;
по одному предмету на слот для владельца. Надевание в занятый слот должно
атомарно возвращать прежнюю вещь в рюкзак и надевать новую. Надетый предмет
не занимает ячейку рюкзака; снятие требует свободной ячейки. Его нельзя удалить,
разделить или перенести до снятия. Извлечение из контейнера не является
снятием экипировки.
Бонусы сохраняются как производный `equipmentBonuses`; базовые характеристики
персонажа и требования изучения навыков не переписываются. Бой получает сумму
базы и бонусов при старте, после чего сохраняет снимок.

Зелья применяются командой боя. Постоянный экземпляр служит шаблоном для
изолированного боевого инвентаря; расход в бою пока не меняет постоянное имущество.
Оружие и ресурсы нельзя использовать как лечебный предмет. Параметры лечения
читаются из снимка каталога, а не из фиксированной подписи кнопки. В новых
боях зелье доступно только до перестановки и заменяет применение навыка за ход;
перестановка после зелья обязательна. Подробнее — [combat.md](combat.md).

Свиток из основного рюкзака выдаёт навык первого уровня и расходует одну единицу
в той же транзакции. Уровень уже известного навыка он не повышает; повторное
чтение такого навыка отклоняется без расхода. Улучшение выполняется за очки.

## Предложения для развития

Переход к [расширяемым характеристикам](character.md) должен заменить
`bonuses: Partial<Stats>` единым списком постоянных модификаторов по ID
характеристики. Они используют те же операции прибавки/процента/множителя,
что и [эффекты навыков](skill-effects.md), и применяются до боевого снимка.
Этот переход пока спроектирован; действующие бонусы и поведение предметов выше
сохраняются. Добавление характеристики не должно требовать нового поля предмета.

Эти операции и группы пока не реализованы:

| Группа / функция | Предлагаемые действия |
| --- | --- |
| Ключи | Открыть конкретный замок, расходовать ключ по настройке |
| Квестовые предметы | Передать персонажу задания, проверить условия сдачи |
| Трофеи и ценности | Продать, обменять, сдать коллекцию |
| Рецепты и чертежи | Изучить рецепт, проверить уже известный рецепт |
| Оружие и экипировка | Ремонт, заточка, зачарование, разбор |
| Ресурсы | Крафт, переработка, объединение по рецепту |
| Общие удобства | Избранное/защита от удаления, сортировка, поиск, журнал владения |

Торговля, крафт и задания должны получить собственные модули, использующие
серверные операции инвентаря; не следует помещать их сценарии в контроллеры
предметов или произвольно изменять таблицы инвентаря.
