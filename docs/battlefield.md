# Модуль боевого поля

Поле отделено от персонажей, урона, энергии и хранения боя. Чистая реализация
находится в `packages/core/src/battlefield`, серверный адаптер — в
`modules/battlefield`, клиентское представление, настройки и выбор клеток — в
`features/battlefield`. Правила совпадений реализованы только в чистом модуле.

## Создание и параметры

```ts
import { createBattlefield, findBattlefieldMove, moveBattlefield } from '@game/core';

const field = createBattlefield({
  size: { rows: 6, cols: 10 }, // либо size: 8 для квадрата 8 × 8
  elementTypes: ['fire', 'water', 'earth'],
});
const move = findBattlefieldMove(field.board)!;
const result = moveBattlefield(field, move.from, move.to);
```

`size` — целое число для квадрата либо `{rows, cols}` для прямоугольника. Размер
по умолчанию — 8 × 8 для совместимости существующих вызовов. Каждая сторона
должна быть от 1 до 32; геометрия должна допускать перестановку с линией из трёх.
Допустимы, например, 3 × 3, 2 × 3 и 1 × 4; 2 × 2 и 1 × 3 отклоняются.

`elementTypes` — список разрешённых типов. Если параметр не передан, используется
полный набор `fire`, `water`, `earth`, `air`, `physical`, `defense`. Явно переданный пустой
список не означает полный набор: он отклоняется. Нужно от 2 до 32 различных
непустых строк длиной до 64 символов. Чистый модуль поддерживает произвольные
строковые типы; REST создания игрового боя разрешает шесть игровых типов,
чтобы они соответствовали модели энергии и интерфейсу игры.

Генерация и каждое заполнение используют только заданные типы. Начальное поле
не должно иметь готовых совпадений и должно иметь хотя бы один допустимый ход.
Генератор делает ограниченное число случайных попыток; детерминированный запасной
вариант гарантирует завершение даже при постоянном корректном RNG. Типы не
обязаны все присутствовать одновременно на маленьком поле, но набор допустимых
типов сохраняется полностью.

Создание возвращает `Battlefield = {board, config}`. `config` содержит
нормализованные `{size: {rows, cols}, elementTypes}`. Список и конфигурация
копируются; изменение результата не меняет переданные настройки.

## Результат хода

`moveBattlefield(field, from, to, random?)` возвращает:

```ts
{
  board,       // новое стабильное поле с допустимым следующим ходом
  config,      // размер и разрешённые типы
  direct:    { count: 3, byType: { fire: 3, water: 0, earth: 0 } },
  generated: { count: 3, byType: { fire: 0, water: 3, earth: 0 } },
  total:     { count: 6, byType: { fire: 3, water: 3, earth: 0 } },
  cascades: 1,
  steps: [
    { source: 'direct', removed: { count: 3, byType: { fire: 3, water: 0, earth: 0 } } },
    { source: 'generated', removed: { count: 3, byType: { fire: 0, water: 3, earth: 0 } } },
  ],
  shuffled: false,
  regeneration: null,
}
```

Числа выше — пример результата, а не гарантированный исход случайного хода.

- `direct` — все горизонтальные и вертикальные совпадения первого этапа сразу
  после перестановки, до падения и заполнения.
- `generated` — сумма совпадений всех последующих этапов после падения и
  генерации недостающих элементов. Сюда входят также старые элементы, которые
  упали и вошли в новую линию; это разделение по этапам, а не возрасту фишек.
- `total` — сумма `direct` и `generated` по количеству и каждому типу.
- `byType` содержит ключи разрешённых типов, в том числе нули.
- `steps` сохраняет порядок этапов; первый всегда `direct`, остальные `generated`.
- `cascades` — число дополнительных этапов, без первого прямого совпадения.
- `shuffled` — после сокращений не осталось хода, поэтому поле сгенерировано
  заново с тем же размером и набором типов. Это также выполняется при лимите
  каскадов. Замена клеток при перегенерации не считается сокращением и не даёт
  дополнительные награды. `regeneration` указывает `no-moves`, `cascade-limit`
  либо `null`, когда перегенерации не было.

Линия состоит минимум из трёх одинаковых элементов. Пересечение горизонтальной
и вертикальной линии учитывает общую клетку один раз на этапе. После удаления
элементы падают вниз в своих столбцах с сохранением порядка; новые появляются
сверху. Совпадения удаляются до стабильного состояния. Максимум — 100 этапов,
включая первый. Если каскад продолжается, поле генерируется заново, а отчёт
содержит все выполненные сокращения и `regeneration: "cascade-limit"`.
Это позволяет завершать ходы даже на двухтипных полях с длинными каскадами.
Неразрешённые совпадения последнего заполнения заменяются вместе с полем,
а не добавляются к счётчикам сокращений.

Координаты — `{row, col}`, индексация с нуля. Перестановка разрешена между двумя
соседними по стороне клетками и должна создать совпадение. Проверяются реальные
границы матрицы, соответствие конфигурации и отсутствие посторонних типов.
До хода поле должно быть стабильным. Исходный объект не изменяется, включая
ошибочные ходы и ошибки генерации; замороженные входы также поддерживаются.

## Подключение к бою

`BattlefieldModule` экспортирует `BattlefieldService`: `create`, `move`,
`possibleMove`. Он реализует контракт `BattlefieldEngine`. `BattlesService`
передаёт его в чистый боевой движок для создания поля, ходов игроков и NPC.
Модуль поля не вызывает сервисы боя и не знает о его репозитории.

Поле и его конфигурация принадлежат агрегату боя и сохраняются вместе с ним в
PostgreSQL JSONB. Отдельного дублирующего хранилища поля нет. `Battle.board`
остаётся матрицей для совместимости; `Battle.battlefield` хранит конфигурацию.
`Battle.boardMoves` содержит результаты перестановок последней успешной команды
с `actorId`, `from`, `to` и отчётом сокращений. Снимок не дублируется внутри
каждого отчёта. Перед новой командой отчёты очищаются. Если вслед за ходом игрока
выполняется ход NPC, сохраняются оба отчёта со своими актёрами; один не заменяет
другой. Максимум сохраняется 11 отчётов: игрок и до 10 автоматических ходов.

Модуль боя использует `direct` и `generated` по [правилам боя](combat.md):
прямые обычные типы открывают навыки, все обычные сокращения дают энергию;
прямая защита даёт временный бонус, вторичная — только энергию защиты.
Поле не наносит урон и не усиливает силу навыка количеством клеток. Команда, NPC, отчёты,
награждение и outbox сохраняются одной транзакцией; ошибка поля откатывает её.
REST-ответ и WS-снимок содержат одинаковые параметры и отчёты.

Старые бои без `battlefield` и `boardMoves` продолжают читаться. При первом ходе
размер восстанавливается из матрицы. Для активного старого боя используется
прежний пятицветный набор и прежние боевые правила; новые бои имеют шесть
типов. Миграция матрицы активного боя не нужна.
Старые функции `createBoard`, `matches`, `possibleMove`, `resolveSwap` сохранены
как совместимые адаптеры. У `resolveSwap` прежние `energy`, `count` и `cascades`
(включает первый этап) и прежняя ошибка при лимите каскадов; новый код должен
использовать явный контракт поля с безопасной перегенерацией.

## REST и интерфейс

Спроектированное расширение целей навыка описано в
[skill-effects.md](skill-effects.md#цель-поле-заморозка-клетки). Клеточные эффекты
ещё не реализованы. Будущий `cell_freeze` должен храниться оверлеем координаты
в агрегате боя, а поле — принимать нейтральные ограничения перестановки.
Проверка игрока, поиск хода NPC и проверка доступных ходов должны учитывать
одни ограничения; типы фишек и отчёты сокращений сохраняют текущий смысл.
В интерфейсе выбор цели-клетки должен быть отдельным режимом от перестановки.

Параметры передаются при создании боя:

```json
{
  "name": "Поле 6 × 10",
  "characterId": "00000000-0000-4000-8000-000000000001",
  "kind": "bot",
  "battlefield": { "size": { "rows": 6, "cols": 10 }, "elementTypes": ["fire", "water", "earth"] }
}
```

Маршрут остаётся `POST /api/battles`. `battlefield` и `elementTypes` можно не
передавать для стандартного размера 8 × 8 и всех шести типов. Изменение матрицы выполняется
только через `POST /api/battles/:id/actions` с `{characterId, version, action}`;
клиент передаёт координаты, а не собственный результат или сгенерированное поле.
Неверные настройки/координаты дают 400, устаревшая версия — 409.

В форме комнаты доступны строки, столбцы и выбор типов, включая защиту. Клиент блокирует
недопустимую конфигурацию, сервер повторяет проверку. Сетка, подпись размера
и координаты строятся из матрицы. После перестановки показываются прямые
сокращения, сокращения при заполнении и их типы. Если в ответе есть отчёт игрока,
показывается он; иначе — последний отчёт NPC с его именем. Визуализация не
пересчитывает сокращения локально. Поле работает при недоступном WS через
существующую REST-синхронизацию боя.
