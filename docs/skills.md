# Навыки: операции и уровни

Здесь описана реализованная модель v1:
[цели, составные эффекты, бафы и длительность](skill-effects.md) и
[расчёт от расширяемых характеристик](character.md). Расчёт характеристик уже
реализован: в новых боях сила ранга задаёт коэффициент физической/магической
мощи или силы лечения. Прежние снимки без реестра сохраняют плоскую силу.
Цели участников, составные эффекты, бафы/дебафы, их сроки и очищение уже
реализованы вместе с периодическими эффектами и щитами. Изменение поля остаётся следующим этапом.

Навык в каталоге и навык персонажа — разные сущности. MongoDB `skills` хранит
описание и баланс. PostgreSQL `characters.data` хранит `learnedSkillIds` и
`skillLevels`: уровень каждого известного навыка. Неизвестный навык имеет уровень
0, изученный — от 1 до 10. Старый изученный навык без записи уровня читается как 1.

| Операция | Поведение |
| --- | --- |
| Получить описание / список | Чтение каталога без изменения персонажа |
| Получить известные навыки | Текущие уровни и рассчитанная сила |
| Выучить | Проверить очки, хотя бы один навык каждого родительского узла, обязательные зависимости, уровень и базовые характеристики персонажа; списать `learning.pointCost`, выдать уровень 1 |
| Улучшить | Требуется известный навык, свободные очки и совпадение `expectedLevel`; повысить уровень на один |
| Получить в награду (`grant`) | Серверная выдача уровня 1 без затрат и требований обучения; повтор не повышает уровень и не дублирует навык |
| Применить | Боевой сценарий проверяет фазу, энергию, цель и перезарядку |

`Skill.progression`: `maxLevel` (по умолчанию 10, допустимо 1–10), `pointCost`
(по умолчанию 1), `powerPerLevel` (по умолчанию 1). Эти значения хранятся в каталоге;
обновление MongoDB добавляет настройки только там, где они отсутствуют.
Сила уровня N: `power + (N - 1) × powerPerLevel`. Улучшение не меняет стоимость
энергии, перезарядку и зависимости дерева. Дополнительного требования к уровню
персонажа для улучшения пока нет. Базовый «Удар» также можно улучшать.

У составного навыка `effects[]` каждое поле растёт независимо: величина — по
весам/коэффициентам выражения, шанс — по собственному приросту, длительность —
по отдельному выражению либо остаётся числом. Отсутствующий прирост равен нулю;
`powerPerLevel` не является множителем всех параметров составного навыка.
Пример с растущим уроном и фиксированным шансом стана и реализованный пропуск хода при оглушении — в [skill-effects.md](skill-effects.md#независимый-рост-параметров-навыка).

Покупка навыка и улучшение выполняются под блокировкой персонажа. Повтор покупки
не списывает очки. Улучшение требует `expectedLevel`: если другой запрос уже
изменил уровень, возвращается 409; недостаток очков или максимальный уровень —
400. Неудачная операция не меняет очки и уровень.

`SkillsService.grant(characterId, skillId, transaction?)` — публичная операция
для других серверных модулей. Бесплатная выдача не открыта отдельной клиентской
командой. Реализованный источник выдачи — свиток: расход предмета и получение
навыка сохраняются одной транзакцией. Если навык уже известен, свиток не тратится.

При старте боя фиксируются уровни навыков, контент и характеристики с экипировкой.
Улучшение после старта не меняет текущий бой. Бот копирует уровни игрока; NPC волн
пока используют уровень 1. Старые боевые снимки без уровней продолжают работать
как уровень 1. Клиент показывает текущую силу, уровень `N / 10`, цену улучшения
и причины недоступности; окончательная проверка всегда выполняется сервером.

## Старт и применение в бою

Новый персонаж и каждый герой из `init` начинают с уровня 1 без изученных
навыков: `learnedSkillIds: []`, `skillLevels: {}`, 3 свободных очка навыков
и 5 очков характеристик. Дерево навыков доступно сразу по `/#skills`; начальные
узлы изучаются за очки, остальные показывают требования. Шаблон героя только
рекомендует направление. «Удар» также изучается за 1 очко и стоит
1 общую энергию. Один общий запас ограничен 200; рост уровня
персонажа не увеличивает этот лимит.

После допустимой перестановки сервер должен предлагать все изученные навыки.
Энергия, КД и живая цель определяют enabled/reason. Совпавшая школа даёт
персональный `matchPowerBps`: 3/4/5/6/7+ прямых клеток — ×1.5/1.75/2/2.25/2.5.
При другом типе или отсутствии совпадения коэффициент ×1. Каскады начисляют
энергию после применения. `matchBonus: false` отключает усиление для
универсального приёма. Проверка и превью выполняются сервером.

Требования изучения проверяются по чистой базе без экипировки и временных
эффектов. В новой модели прежнее требование `attack` означает физическую
мощь для физических навыков и магическую для стихийных. Новое поле
`learning.requirements` позволяет ссылаться на первичные и производные ID
реестра. Боевой ответ `skillChoices.magnitude` показывает рассчитанную
величину до защиты и крита.

## REST

| Метод | Путь | Тело / результат |
| --- | --- | --- |
| GET | `/api/v1/skills`, `/api/v1/skills/:id` | Каталог / описание |
| GET | `/api/v1/characters/:id/skills` | Известные навыки с `level`, актуальной `power` и `progression` |
| POST | `/api/v1/characters/:id/skills` | `{skillId}` → персонаж |
| POST | `/api/v1/characters/:id/skills/:skillId/upgrade` | `{expectedLevel}` → персонаж |

## Эффекты и расширение

Новые навыки имеют явный `targeting`, упорядоченный массив `effects` и
формулы величин от характеристик. Старые `effect` и `power` сохраняются для
совместимости. Поддерживаются цели: себя, один союзник, союзники, один
противник и противники. Клетка поля остаётся следующим этапом. Цель не выводится из признака лечения.
Одиночный участник или клетка выбираются до подтверждения применения;
отмена выбора бесплатна.

Базовые характеристики: сила, ловкость, интеллект, выносливость, удача.
Новая характеристика регистрируется данными, затем используется по ID
в формулах, требованиях и модификаторах. Ранг навыка по-прежнему 1–10;
в новой модели он увеличивает коэффициенты эффектов, а не готовую силу.
Правила наложения, продолжительности, ошибок, совместимости и этапы реализации
зафиксированы в [skill-effects.md](skill-effects.md); порядок расчёта и рост
характеристик — в [character.md](character.md).

На будущее предлагаются: забыть навык с проверкой зависимостей, сбросить ветку,
наборы активных навыков и временно выданные способности. Возврат очков и стоимость
сброса требуют отдельного решения; сейчас эти действия не реализованы.

В серверный каталог входят 30 простых и 25 составных навыков. Составные
включают щиты, периодический урон/лечение, контроль, модификаторы, массовые
действия и очищение. Они изучаются за обычные очки, без бесплатной выдачи.

## Стартовая настройка каталога v1

Запас 200; каждая клетка любого типа даёт 1. Базовые атакующие навыки стоят
1–3, поддержка 8–15, сильные 20–35, высшие 60–80. Сила простого навыка
растёт на 1 за ранг, всего до 10 рангов. Универсальные физические приёмы
«Собраться», «Подсечка», «Сбить прицел», «Боевая собранность» расширяют
выбор без зависимости силы от цвета поля. Цены — в [skill-balance.md](skill-balance.md).

Новый герой получает 3 очка навыков и 5 очков характеристик; уровень даёт
1 и 5 соответственно. Арсенал показывает все известные навыки и их КД;
окно применения дополнительно показывает серверное усиление каждого.

## Вкладки и дерево альтернативных узлов

У каждой школы отдельная вкладка: огонь, вода, земля, воздух и физические
навыки. Внутри виден один общий начальный узел, затем ответвления. Узел
может содержать несколько навыков; они не требуют друг друга. Для открытия
дочернего узла достаточно изучить **любой один навык** предыдущего узла.
Если указано несколько родительских узлов, нужен один навык каждого из них.
Улучшения одного навыка не заменяют недостающий предыдущий узел. Выбор одного
направления не блокирует другие школы или соседние направления.

| Школа | Общий исток | Ответвления |
| --- | --- | --- |
| Огонь | Пробуждение пламени | Пламя и разрушение → Власть над огнём; Путь феникса → Сердце феникса |
| Вода | Первый источник | Лёд и оковы → Вечная мерзлота; Живой поток → Сила обновления |
| Земля | Сила земли | Разлом и хватка → Гнев гор; Камень и корни → Древо жизни |
| Воздух | Дыхание ветра | Сердце бури → Повелитель бури; Попутный ветер → Благословение неба |
| Физические | Основы мастерства | Искусство натиска → Мастер оружия; Стойкость и хитрость |

Пример: любой навык «Пробуждения пламени» открывает узел с «Огненным шаром»
и «Ожогом». Изучение одного «Ожога» открывает узел с «Инферно», «Метеоритным
дождём» и «Очищающим пламенем»; «Огненный шар» для этого не обязателен.
Индивидуальные требования к уровню, характеристикам и очкам сохраняются.
Путь феникса открывается независимо, через общий исток, и не считается освоенным
только из-за изучения разрушительных навыков.

Каталог `skills` хранит `learning.branch: {id, name, parents, order}` у каждого
участника узла. Все объявления одного узла должны совпадать и относиться
к одной школе. Состав узла определяется навыками с тем же `branch.id`.
`parents` — ID узлов, не ID навыков. `order` отвечает только за порядок показа.
Иконка карточки задаётся `Skill.icon` из проверяемого набора SVG-эмблем.
Иконка и порядок не участвуют в боевых расчётах.

В начальном каталоге прежние последовательные `learning.prerequisites`
заменены узлами. Сам контракт `prerequisites` сохраняет смысл обязательных
индивидуальных навыков для отдельного пользовательского контента; при наличии
обоих типов зависимостей должны выполняться оба. Каталог отвергает неизвестные
родительские узлы, ссылки на другую школу, противоречивые объявления,
повторные родители, циклы и неразрешимые смешанные зависимости. Чистые правила
находятся в `core/skill-tree.ts`, раскладка каталога — `core/skill-tree-content.ts`.
Никакое игровое поведение не выбирается по ID конкретного навыка.

`learningBlockers` и `learnSkill` проверяют узлы; `SkillsService.learn` выполняет
обучение под прежней транзакционной блокировкой персонажа. Повторный запрос не
дублирует навык и не тратит лишние очки. Клиент использует общий расчёт только
для подсказок; окончательное решение принимает сервер по свежему каталогу.
Вознаграждение/свиток по-прежнему может выдать навык через `grant`; такой навык
считается освоенным участником узла и может открыть следующий узел.
Уже изученные навыки и ранги не отзываются после изменения дерева.

На карточке постоянно видны эмблема, имя, описание, энергия, КД, минимальный
уровень и действие обучения/улучшения. Разворачиваемый блок показывает полные
требования и действие. Линии показывают реальные родительские узлы, освоенные
связи подсвечены. Цвет дополнен подписями состояний. На телефоне узлы переходят
в одну колонку, связи идут по боковому полю; горизонтальной прокрутки страницы
нет. Вкладки поддерживают стрелки, Home/End и сохраняют выбор при покупке навыка.

У новых героев остаются уровень 1, ноль изученных навыков, 3 ОН и 5 очков
характеристик. Ранги, цены, характеристики и энергия не изменены. Новые тома
получают дерево из seed. Для работающего каталога применяется явное обновление
полей `icon`, `learning.branch`, `learning.prerequisites` начальных навыков;
автоматическая перезапись ручных настроек при старте не добавляется.
Персонажи, инвентари, распределённые очки и PostgreSQL-схема не меняются.
