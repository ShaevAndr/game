# Группы игроков

Статус: реализовано в базовой v1. Группы принадлежат модулю `parties`, а не чату.
Связанные правила: [социальные связи](social.md), [чат](chat.md),
[архитектура](architecture.md).

## Состав и приглашения

- Максимум **6 игроков, включая лидера** — явное требование владельца проекта.
  Аккаунт может состоять только в одной группе и занимает одно место. Участник
  хранит `playerId` аккаунта и выбранного при вступлении персонажа. Смена героя
  в сессии не выводит из группы; кнопка «Сменить персонажа» явно обновляет героя
  участника на текущего своего героя. Дружба и ЧС остаются привязаны к аккаунту.
- Первое приглашение автоматически создаёт группу из приглашающего лидера.
  Отказ не распускает её. Приглашать, отменять приглашения, передавать лидерство,
  исключать участников и распускать группу может только лидер. Все участники
  могут выйти. Самого себя пригласить или исключить нельзя.
- Меню чужого автора в чате, список друзей и панель группы предлагают
  «Пригласить в группу». Цель — аккаунт; при согласии вступает его текущий
  выбранный персонаж. Персонаж отправителя сохраняется в приглашении снимком.
- Получатель видит модальное окно: «Персонаж X приглашает вас в группу.
  Принять приглашение?» Кнопки «Принять» и «Отказаться». Escape равен отказу;
  нажатие на фон само по себе не меняет состояние. При отказе приглашение
  закрывается и больше не появляется, при согласии игрок атомарно вступает.
  Несколько приглашений показываются последовательно, по времени создания и ID.
- Приглашение действует 120 секунд, после чего исчезает. Лидер может отменить
  его раньше. Одновременно допускается до 12 действующих приглашений группы
  и до 12 входящих игрока. Повторное приглашение в ту же группу возвращает
  прежнее действующее приглашение, не обновляя срок. После отказа той же паре
  запрещено отправлять новое приглашение 30 секунд.
- Приглашения не резервируют места: вместимость повторно проверяется при
  принятии. После заполнения группы остальные её приглашения отменяются.
  Вступление отменяет остальные входящие приглашения игрока. При смене лидера
  или роспуске прежние приглашения группы отменяются.
- ЧС с любой стороны запрещает приглашение и принятие с одинаковой общей
  ошибкой, не раскрывающей направление блокировки. Блокировка окончательно
  инвалидирует прежние приглашения пары: разблокировка их не восстанавливает.
  Состав уже существующей группы от ЧС не меняется.

## Управление и интерфейс

Панель группы находится слева под персонажем и доступна на игровых экранах.
Она показывает число участников `N / 6`, компактные карточки с именем героя,
уровнем, инициалом-портретом и короной/текстом «Лидер», меню управления,
отправленные приглашения, выбор игрока и кнопку приглашения. Ложных HP,
статусов онлайна, координат и автоматического включения в бой нет.
Данные уровня героя перечитываются через публичный сервис персонажей.

За ориентир взаимодействия принят [контекстный список действий Perfect World](https://world2.gameflier.com/newplayer/interface_i.html):
приглашение из меню игрока. Компактный список состава и отметка лидера
адаптируются к текущему интерфейсу игры; изображения клиента PW не копируются.

Выход лидера передаёт лидерство первому оставшемуся по порядку вступления.
Выход последнего участника удаляет группу. Роспуск освобождает всех участников.
Роль и права проверяет сервер. Группа сохраняется после отключения клиента;
выход из аккаунта или смена героя не распускают её. Групповой чат, совместный
вход в бой, общий лут и награды требуют отдельных сценариев и пока не включены.

## REST, повторы и конкурентность

- `GET /api/v1/parties` — только своя группа, доступные входящие и исходящие
  приглашения, список имён аккаунтов для выбора, лимит и серверное время.
- `POST /api/v1/parties/actions` — `{operationId: UUID, expectedPartyId: UUID|null,
  expectedRevision: nonnegative integer, action}`. Без группы — `null`, `0`.
  Действия: `invite {targetPlayerId}`, `accept|decline|cancel {invitationId}`,
  `transfer|kick {targetPlayerId}`, `leave`, `disband`, `change-character`.
  Аккаунт и действующий персонаж берутся из bearer-сессии; чужой герой не
  принимается из тела команды. Для новых команд нужен выбранный свой герой.
- Новая команда возвращает 201, точный повтор — 200 и сохранённый результат.
  Изменённое тело с тем же ключом — 409. Тело строгое. Конфликт группы,
  ревизии, занятого места или истёкшего приглашения — 409; нарушение роли/ЧС —
  403, неверная команда — 400, неизвестный адресат — 404, нет сессии — 401.
- Клиент сверяется через REST каждые 2 секунды, при фокусе окна и после
  команды. Нового WS нет. Диалог работает и при свёрнутом чате. Сетевой сбой
  сохраняет команду с тем же ID в `sessionStorage`; после перезагрузки есть
  явное повторение. Пока исход не определён, новая команда не отправляется.
  Истёкшее приглашение скрывается локально по серверным часам и проверяется
  сервером независимо. Ошибка принятия перечитывает состав и приглашения.

`init` создаёт `parties` (агрегат с ревизией), `party_members` (уникальное
членство аккаунта и ссылка на персонажа), `party_invitations` и
`party_operations` (квитанции аккаунта). Группа, индекс членства, приглашения
и квитанция коммитятся одной `UnitOfWork`; ошибки всё откатывают. История
приглашений нужна для повторов и ограничения повторной отправки, TTL пока нет.

На текущем небольшом монолите граф групп сериализуется транзакционной
блокировкой домена в PostgreSQL-адаптере. Это осознанное простое решение для
гонок принятия в разные группы и последнего места; сервис не содержит SQL.
При росте времени ожидания блокировки его можно заменить упорядоченными
блокировками участников/групп без изменения публичных контрактов.
Порядок: квитанция → социальные блокировки в порядке ID → блокировка графа
групп → изменения. Социальная политика возвращает отдельную ревизию
допуска приглашений, изменяемую при block/unblock; она не раскрывается клиенту.
Чтение фильтрует приглашения по этому допуску до выдачи имён и текста.

## Проверки

Нужны: отказ без вступления и повторного окна; принятие только адресатом;
сохранность после рестарта; повтор команды; две группы для одного игрока;
гонка за шестое место; запреты обычному участнику; передача лидерства,
исключение, выход и роспуск; срок и отмена; ЧС с последующей разблокировкой;
откат всей команды при ошибке записи; диалог и компактная панель на мобильном.
Перед завершением — `pnpm check`, `test:migrations`, `test:infrastructure`.
