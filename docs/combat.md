# Бой: поле, энергия, выбор навыка

Канонические правила новых боёв — `combatVersion: 2`. Расчёты находятся в
`packages/core/src/combat/matched.ts`, общий жизненный цикл — в `combat/common.ts`.
Поле отвечает только за сокращения; [battlefield.md](battlefield.md) описывает
его параметры и отчёты. Сервер должен проверять фазу, тип, энергию, цель и
перезарядку. Клиент должен показывать серверный `skillChoices`.

Следующая версия пока только спроектирована:
[явные цели и эффекты навыков](skill-effects.md),
[характеристики и производные величины](character.md). Она сохраняет энергию
и открытие навыков прямыми типами, но меняет формулы и протокол выбора цели.
Ни новые криты, ни формулы защиты, ни бафы из этой спецификации не применяются
к текущим снимкам v2 до отдельной реализации.

## Типы клеток и энергия

Поле должно поддерживать шесть типов: `fire`, `water`, `earth`, `air`,
`physical`, `defense`. Навыки имеют один из первых пяти типов; навыков защиты
нет. Набор поля можно ограничить при создании комнаты.

| Сокращение | Энергия | Другой результат |
| --- | --- | --- |
| Прямое, стихия или физический тип | +1 за клетку соответствующего типа | Открывает изученные навыки этого типа |
| Вторичное, стихия или физический тип | +1 за клетку соответствующего типа | Не открывает навыки |
| Прямое, защита | Не начисляется | Временная защита пропорционально числу клеток |
| Вторичное, защита | +1 энергии защиты за клетку | Не даёт временную защиту и не открывает навыки |

Каждый запас энергии ограничен 30, включая энергию защиты. Прямые обычные клетки
начисляют энергию и при наличии изученного навыка. Вторичные — все совпадения
после первого удаления и заполнения, включая упавшие старые клетки. Пересечение
линий учитывается один раз на этапе. Перегенерация поля не даёт энергии.

Энергия защиты пока только накапливается: расходование отдельной операцией
не реализовано. Она не должна автоматически превращаться во временную защиту.

## Последовательность хода

1. В фазе `before` игрок должен выполнить одну допустимую перестановку.
2. Движок должен разрешить прямые совпадения и все каскады, начислить всю
   энергию, установить временную защиту и сохранить отчёт сокращений.
3. В фазе `choose` видны **только изученные навыки типов прямого совпадения**.
   Если прямо совпали несколько типов, видны навыки каждого из этих типов.
   Вторичный тип не должен открывать навык, даже если энергии достаточно.
4. Все подходящие изученные навыки должны быть видны. Недостаток энергии или
   перезарядка делает кнопку неактивной; `SkillChoice.reason` содержит причину.
   Если подходящих навыков нет, ход заканчивается автоматически. Если навыки
   есть, но все недоступны, игрок может сохранить энергию и завершить ход.
5. Можно применить один доступный навык либо завершить ход без применения.
   Сервер сначала проверяет цель, затем списывает `Skill.cost` из запаса типа
   навыка. Применение сразу завершает ход; энергия, оставшаяся в запасе,
   сохраняется для следующих ходов этого боя.

«Удар» стоит 3 физической энергии и не имеет перезарядки. Обычное прямое
совпадение из трёх физических клеток позволяет применить его сразу. Другие цены
берутся из каталога; стоимость должна быть от 1 до 30. Стартовый атакующий навык
должен стоить не более 3 и не иметь перезарядки.

Клетки не наносят урон и не усиливают навык количеством сокращений. Урон:
`max(1, сила навыка текущего уровня + атака − базовая защита цели − временная защита)`.
Лечение равно силе навыка и ограничено максимальным HP; целью может быть живой
союзник. Урон требует живого противника. Перезарядка 2 запрещает применение в
следующие два собственных хода.

Зелье можно использовать в фазе `before` вместо навыка. После зелья перестановка
остаётся обязательной; энергия и защита начисляются, затем ход завершается.
Списание зелья изолировано внутри боя, как описано в [items.md](items.md).

## Временная защита

Прямые клетки `defense` дают `число клеток × defensePerTile` защиты.
По умолчанию коэффициент равен **10**: три клетки дают +30. Значение настраивается
в `settings.balance.combat.defensePerTile`, фиксируется в снимке контента боя.
Бонус хранится отдельно в `Fighter.guardDefense`; базовая характеристика
`stats.defense` не должна изменяться.

Бонус действует до начала следующего собственного хода: в командном бою он
защищает от всех промежуточных ходов противников. Полученный удар не расходует
бонус. При начале собственного хода бонус сбрасывается. Интерфейс должен
показывать бонус на карточке бойца и отдельно от базовой защиты персонажа.

## Персонажи и совместимость

Новый персонаж любого шаблона должен получать только физический «Удар» первого
уровня и **4 свободных очка навыков**. Шаблон рекомендует развитие; профильный
навык нужно изучить отдельно. Навык можно улучшить до 10-го уровня. Рост уровня
персонажа больше не увеличивает лимит энергии.

Миграция PostgreSQL `006_matched_combat` один раз добавляет существующим героям
2 очка, ограничивает запасы и ёмкость 30, добавляет запас защиты. Она сохраняет
навыки, их уровни, предметы, опыт и боевые снимки. MongoDB при переходе на v2
обновляет стартовый запас до 4 и отключает рост ёмкости; недостижимые требования
`learning.stats.maxEnergy > 30` снижаются до 30. Старый бесплатный «Удар» получает
стоимость 3. Описания стандартных шаблонов обновляются только при точном
совпадении с прежним стандартным текстом.

Уже активные бои без `combatVersion` должны завершаться по сохранённым правилам
через `combat/legacy.ts`: прежние режимы, цена «Удара», урон клеток и лимиты
сохраняются в их снимках. Новые комнаты используют только `on-match` v2; прежний
параметр `rule` принимается для совместимости, но не выбирает старую механику.
Старые ожидающие комнаты переходят на v2 при старте; стандартное пятицветное
поле получает шестой тип с сохранением размера. Явный ограниченный набор
типов сохраняется.

## REST и сохранение

`POST /api/battles/:id/actions` принимает `{characterId, version, action}`.
Перестановка v2: `{type: 'swap', from: {row, col}, to: {row, col}}`; цель нужна
только для `{type: 'skill', skillId, targetId}`. `{type: 'end'}` допустим после
сокращений; `{type: 'item', itemId}` — до перестановки.

Снимок содержит `matchedElements`, `skillChoices`, `guardDefense`, все запасы
энергии и отдельные отчёты `boardMoves`. Изменение, автоматический ход NPC,
награды и outbox сохраняются одной PostgreSQL-транзакцией с проверкой версии.
Недопустимый или повторный запрос не должен тратить энергию или выдавать
награду повторно. NPC должен соблюдать тот же порядок и ограничения.
Состояние восстанавливается через REST; WS передаёт снимки открытого боя.
