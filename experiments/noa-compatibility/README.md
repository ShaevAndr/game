# Стенд исследования на noa-engine

Отдельная миниигра с тестовыми персонажами, инвентарём, дропом и рецептами.
[Правила и ограничения](../../docs/noa-engine.md). Основная игра и её
канонические инвентари не используются.

Из корня проекта запустите MongoDB, затем стенд:

```sh
docker compose up -d mongo
cd experiments/noa-compatibility
npm ci
npm run dev
```

Открыть <http://localhost:8090>. База по умолчанию — **`noa_sandbox`** на
`mongodb://127.0.0.1:27017`; можно задать `NOA_MONGO_URL` и `NOA_MONGO_DB`.
Основную базу `elemental_tactics` адаптер не принимает. Каталог, повреждения,
вещи на земле, инвентари и квитанции сохраняются после рестарта стенда.

```sh
npm test
npm run build
npm run test:browser
# Нужна работающая MongoDB; создаётся и удаляется только уникальная test_noa_*.
npm run test:persistence
```

Для браузерных проверок используется `/usr/bin/google-chrome` или
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Если их нет, установите браузер:
`npx playwright install chromium`. Проверка сама поднимает Vite в режиме
`test` на свободном порту с хранилищем в памяти: работающий мир не меняется.
Снимок инвентаря и результаты — в игнорируемой папке `.local/`.
`npm run build` проверяет сборку клиента; для просмотра нужен `npm run dev`
с тестовым HTTP API.

Управление: клик по сцене — захват мыши, мышь — камера, WASD — движение,
пробел — прыжок. **I** открывает инвентарь с выбором оружия/инструмента и
выбрасыванием выбранного количества. **E** подбирает ближайшую стопку.
В разделе строительства выберите чертёж; **ПКМ** устанавливает его с расходом
материалов. 1/2 — кирка/топор, 3 — выбранная постройка. Esc освобождает курсор
или закрывает инвентарь. Пока рюкзак открыт, управление миром приостановлено.

Каждому персонажу доступны тестовые кирка, топор, меч, 80 камней,
16 древесины и **10 смолы**. У прежних персонажей смола однократно пополняется
до 10; потраченные материалы не возвращаются при обновлении страницы.
Каменная кладка требует 40 камней и 1 смолу, деревянный блок — 8 древесины
и 1 смолу. «Начать заново» пересоздаёт только мир стенда и стартовые запасы.

Каталог предметов-объектов находится в MongoDB `items`, рецепты — в
`recipes`, стартовый набор — в `settings`, состояние — в `worlds`.
[catalog.json](catalog.json) используется только для первоначального
наполнения. Обычный рестарт сохраняет изменённые определения.
Например, шанс золота из камня можно изменить в `mongosh` базы `noa_sandbox`:

```js
db.items.updateOne(
  {id: 'stone'},
  {$set: {'worldObject.drops.$[drop].chanceBps': 200}},
  {arrayFilters: [{'drop.itemId': 'gold-ore'}]}
)
```

Это задаёт шанс 2%. Сервер перечитает значение при следующем запросе.
Ссылки, количества, HP и вероятности валидируются до выполнения действий.

`world-view.json` создан настоящим `core/world` без скрытых чанков, seed и
таблиц добычи. Из корня проекта его можно пересоздать:

```sh
docker compose --profile world exec -T -w /app/apps/world world \
  node --require tsx/cjs - \
  < experiments/noa-compatibility/make-fixture.cjs \
  > experiments/noa-compatibility/world-view.json
```

Глубинные воксели пока остаются непроходимыми неизвестными блоками.
Настоящая авторизация, персонажи, бои, PostgreSQL и RabbitMQ не подключены.
Движок noa — MIT, Babylon.js — Apache-2.0; их код не копируется в репозиторий.
