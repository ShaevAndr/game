# Стихии — Tactical Match-3

Сетевой MVP: общее поле «три в ряд» и пошаговый бой. Node.js 22+, TypeScript, NestJS, React, PostgreSQL + Kysely, MongoDB, Redis, BullMQ, Socket.IO, pnpm workspaces.

Правила структуры и взаимодействия: [архитектура](docs/architecture.md). Инструкции для дальнейших изменений: [AGENTS.md](AGENTS.md).

## Запуск всего проекта

На новом компьютере установите Git и Docker с Compose (в Windows — запущенный Docker Desktop с Linux-контейнерами). Node.js и pnpm для этого способа не нужны:

```sh
git clone https://github.com/ShaevAndr/game.git
cd game
docker compose up -d --build
```

Откройте **http://localhost:8088**. Compose собирает и запускает frontend, backend, PostgreSQL, MongoDB и Redis. Для просмотра журналов используйте `docker compose logs -f`. Запуск в текущем терминале вместо фона: `docker compose up --build`.

Порт можно изменить через `GAME_WEB_PORT` в `.env`, затем выполнить `docker compose up -d`. Compose автоматически использует этот же порт для `WEB_ORIGIN` сервера. Если в Windows на `localhost:8080` появляется `Access Error: 404 -- Not Found`, проверьте конфликт со сторонним `ApplicationWebServer`: Windows и WSL могут отдавать разные страницы по IPv4 и IPv6. По умолчанию игра использует порт 8088.

Миграции PostgreSQL и первоначальное наполнение MongoDB выполняются при старте сервера. Миграция `003_demo_characters` сразу добавляет десять готовых героев 10-го уровня — по два на каждую ветку, с изученными навыками и зельями. На новом устройстве не нужно создавать персонажей вручную. Данные сохраняются в Docker volumes. Остановить проект: `docker compose down`.

Для обновления существующей установки из папки проекта:

```sh
git pull --ff-only
docker compose up -d --build
```

У каждого компьютера собственные базы и прогресс. Git переносит код и начальные данные миграций; для переноса накопленного прогресса нужны резервные копии баз.

### Разработка с обновлением кода

Для разработки установите также Node.js 22+:

```sh
corepack enable
pnpm install
pnpm infra
# Скопируйте .env.example в .env при необходимости изменить настройки.
pnpm dev
```

Клиент: **http://localhost:5173**, сервер: **http://localhost:3001/api**. Vite и Nginx проксируют HTTP API и Socket.IO; клиент использует тот же origin. PostgreSQL и MongoDB обязательны: скрытой подмены на память нет. Redis используется для кэша и очередей; при временном отказе Redis чтение идёт из MongoDB, а архивирование боёв ожидает восстановления в outbox PostgreSQL.

В Windows при блокировке `pnpm.ps1` используйте `pnpm.cmd`. Если Corepack не может записать глобальные shims, можно установить их локально:

```powershell
New-Item -ItemType Directory -Force .corepack-bin
corepack enable --install-directory .corepack-bin
$env:COREPACK_HOME = Join-Path (Get-Location) '.corepack'
$env:PATH = "$(Join-Path (Get-Location) '.corepack-bin');$env:PATH"
pnpm.cmd install
pnpm.cmd dev
```

## Как попробовать

1. Выберите готового героя 10-го уровня в списке персонажей или создайте своего: выберите тип героя и введите имя. Все персонажи доступны каждому, авторизации и владения нет. Выбор хранится отдельно для каждой вкладки.
2. Для одиночной игры выберите **«Бой с ботом»**, создайте комнату и нажмите «Начать бой». Бот получает характеристики и изученные навыки вашего героя и ходит автоматически, включая лечение при низком здоровье. Можно также выбрать подземелье: три волны противников.
3. Для сетевой проверки создайте дуэль или командную комнату, скопируйте приглашение и откройте во второй вкладке/браузере. Выберите **другого** персонажа, вступите в другую команду, начните бой.
4. Выберите противника нажатием на карточку. Затем нажмите две соседние фишки так, чтобы собрать линию из трёх или более. Невалидная перестановка не тратит ход.
5. Совпадения по горизонтали и вертикали, включая каскады, дают энергию: огонь, вода, земля, воздух, физическая сила. Пересечения считаются один раз. Если ходов нет, поле автоматически обновляется.

Для игры с другого устройства откройте `http://IP-компьютера:8088` (или порт из `GAME_WEB_PORT`), разрешив этот порт в локальном firewall. В приглашении используйте доступный другим устройствам адрес вместо `localhost`.

## Правила MVP

| Режим | Порядок действий |
| --- | --- |
| Навык → поле | Необязательный навык, затем обязательная перестановка. Урон от фишек, автоматический переход хода. |
| Навык до / после | Один необязательный навык за ход: до **или** после перестановки. Фишки сразу наносят урон. Ход завершается кнопкой. |
| Поле → выбор навыка | Перестановка даёт энергию, затем обязателен навык. Отдельного урона от фишек нет; число собранных фишек усиливает выбранный навык, включая лечение. |

Базовый «Удар» бесплатен и без перезарядки. Энергия ограничена характеристикой персонажа, отдельно для каждой стихии. По умолчанию фишка даёт 1 энергию; урон от перестановки — `число фишек × 2 + атака − защита` (минимум 1). Навык наносит `сила + атака − защита`, а в режиме выбора после сбора получает дополнительно `число фишек × 2`. Лечение ограничено максимумом HP; можно выбрать живого союзника.

За ход можно применить один навык **или** зелье. Зелье доступно до перестановки в первых двух режимах. Перезарядка `2` блокирует следующие два собственных хода. Пропуск перестановки не разрешён. Погибшие участники пропускаются. Командные бои поддерживают до 3×3 по умолчанию с чередованием команд в очереди; подземелье — до трёх игроков против одного противника в каждой волне.

**Инстансы изолированы:** HP, энергия, перезарядки и расход предметов живут внутри конкретного боя; персонаж служит шаблоном. Расход зелий и собранная энергия не переносятся в другие бои. Опыт, уровень, характеристики, очки навыков и изученные навыки сохраняются в PostgreSQL между боями. Экипировка и постоянное изменение инвентаря после боя пока не реализованы.

## Уровни и дерево навыков

Откройте вкладку **«Навыки»** в верхнем меню или нажмите на очки навыков в карточке персонажа. Экран доступен напрямую по `/#skills`. Пять веток — огонь, вода, земля, воздух и физическая сила. В каждой ветке **шесть навыков и два типа героя**; начальные навыки героев и все зависимости показаны на карточках. У огня, воды, земли и воздуха есть отдельные пути атаки и лечения. Физическая ветка предлагает тяжёлые удары, быстрые атаки и «Второе дыхание» для лечения.

| Ветка | Герои и начальные навыки |
| --- | --- |
| Огонь | Пиромант — «Искра»; Адепт Феникса — «Тепло Феникса» |
| Вода | Хранитель прилива — «Источник»; Маг льда — «Ледяная игла» |
| Земля | Геомант — «Каменный осколок»; Друид — «Сок жизни» |
| Воздух | Заклинатель бури — «Дуновение»; Хранитель ветра — «Дыхание ветра» |
| Сила | Дуэлянт — «Выпад»; Ветеран — «Второе дыхание» |

Тип героя определяет начальный навык, сохраняя возможность развивать все пять веток. Профильный навык изучается по обычным правилам за **1 из 2 стартовых очков**; остаётся 1 очко на выбор. Характеристики одинаковые. Можно выбрать «Странник»: только бесплатный «Удар» и 2 свободных очка. Существующие персонажи сохраняют прогресс и могут изучать новые навыки.

Новый персонаж получает уровень 1, 0 опыта, **2 очка навыков** и бесплатный «Удар». Для изучения сервер одновременно проверяет:

- достаточное количество очков навыков;
- все навыки из `learning.prerequisites`;
- минимальный уровень `learning.level`;
- минимальные характеристики `learning.stats`.

Уже изученный навык нельзя купить повторно. Стоимость изучения `learning.pointCost` отличается от затрат энергии на применение в бою. Очки списываются и навык сохраняется под блокировкой строки персонажа в одной транзакции: две вкладки не могут потратить одно и то же очко.

Награда за победу по умолчанию: **100 XP** за бой с ботом или дуэль, **140 XP** за командный бой, **240 XP** за полное прохождение подземелья. Каждый персонаж победившей команды получает полную награду, включая выбывших союзников. Проигравшие и NPC опыта не получают; за отдельную волну награда не выдаётся. Завершённые до обновления бои не награждаются задним числом.

Порог следующего уровня: `100 + (текущий уровень − 1) × 50`. Остаток опыта сохраняется; за одну победу можно получить несколько уровней. Каждый уровень даёт **2 очка навыков**, **+12 HP**, **+2 атаки**, **+1 защиты**, **+2 лимита энергии**. Настройки находятся в MongoDB: `settings`, документ `id: balance`, поле `progression`.

Завершение боя, запись наград и развитие победителей сохраняются одной транзакцией. В таблице `battle_rewards` первичный ключ `(battle_id, character_id)` запрещает повторное начисление. Строки персонажей блокируются в одинаковом порядке, поэтому награды из разных боёв и изучение навыков не затирают друг друга.

При старте боя набор навыков и характеристики обновляются из персонажей, после чего фиксируются в инстансе. Изучение в другом окне не меняет уже активный бой. Старые персонажи получают недостающие поля развития без сброса уровня, характеристик и инвентаря; недостающие настройки MongoDB добавляются при запуске сервера без перезаписи существующих правок.

## Готовые персонажи и миграции

В миграции `apps/server/src/infrastructure/database/migrations/003-demo-characters.ts` используются фиксированные данные из соседнего JSON-файла. Это настоящий прогресс 10-го уровня: 228 HP, 26 атаки, 12 защиты, лимит энергии 48. У каждого героя изучена своя ветка (6–7 навыков вместе с базовым «Ударом»), остаётся 12–14 очков для других веток. Искра и Феникс представляют огонь, Прилив и Иней — воду, Гранит и Ива — землю, Шторм и Зефир — воздух, Клинок и Оплот — физическую силу.

Миграция выполняется автоматически и учитывается в истории Kysely. Фиксированные UUID и `ON CONFLICT DO NOTHING` предотвращают дублирование и сохраняют уже изменённые имена, опыт и навыки. Новые персонажи, созданные через интерфейс, начинают с уровня 1. Бой с ботом не требует второго персонажа или второй вкладки; характеристики и навыки соперника фиксируются при старте, и NPC не получает опыт.

## Архитектура

```text
apps/server/src/
  modules/      домены: characters, skills, items, inventory, battles,
                rewards, battle-history, content
    <domain>/
      http/          REST-контроллеры и WS gateway
      application/   сценарии и бизнес-сервисы
      ports/         заменяемые контракты хранения и интеграций
      repositories/  PostgreSQL/MongoDB-адаптеры
      *.module.ts    только сборка зависимостей NestJS
  infrastructure/    подключения к PostgreSQL, MongoDB, Redis, BullMQ; миграции
  shared/            контракты транзакций, кэша, очереди; HTTP-фильтры
apps/web/src/
  app/          сборка приложения, навигация и общие действия
  features/     characters, skills, items, inventory, content, arena, battles
    <feature>/  api/ (REST), model/ (хуки), components/ (представление)
  shared/       HTTP-клиент и общие UI-примитивы
packages/core/  чистые типы, Zod-схемы, поле, движок боя и правила развития
scripts/        автоматическая проверка границ архитектуры
docs/          архитектурные правила и потоки данных
deploy/        Nginx для Docker
```

Сервер — единственный источник состояния. Команды проверяют текущего участника, фазу, ресурсы, цели и версию. Изменение инстанса выполняется в транзакции PostgreSQL с `SELECT … FOR UPDATE`; устаревшая версия возвращает HTTP 409. После коммита сервер отправляет снимок в Socket.IO-комнату. Клиент переподписывается и перечитывает снимок после переподключения. При недопустимом действии транзакция откатывается, включая действия NPC.

В JSONB инстанса сохраняются поле, участники с характеристиками, HP, энергия, инвентарь, навыки, перезарядки, очередь, фаза, режим, волна, журнал и **снимок контента**. Активные бои переживают перезапуск сервера. PostgreSQL также хранит версии и историю миграций Kysely.

Текущая конфигурация рассчитана на **один экземпляр NestJS** с фоновыми обработчиками в том же процессе. Redis для очередей и кэша сам по себе не масштабирует WS. При горизонтальном масштабировании нужен общий Socket.IO adapter (например Redis) для доставки событий между процессами. Таймера хода, автоматического поражения при отключении и подбора соперников в MVP нет.

## Изменение контента без изменения кода

База MongoDB: `elemental_tactics`.

| Коллекция | Что хранится |
| --- | --- |
| `skills` | Стихия, стоимость энергии, сила, эффект, перезарядка; `learning`: цена изучения, уровень, зависимости, характеристики и признак стартового навыка |
| `items` | Предметы, сила лечения, имя и описание |
| `enemies` | Характеристики и набор навыков NPC |
| `characterTemplates` | Типы героев: имя, описание, ветка и `skillId` начального навыка первого уровня; его требования должны быть доступны новому персонажу |
| `settings` (`id: balance`) | Начальные характеристики, предметы, урон и энергия от фишки, размер команды, волны; `progression`: награды XP, пороги уровней, очки и прирост характеристик |

Например, изменить силу огненного шара:

```sh
docker compose exec mongo mongosh elemental_tactics --eval 'db.skills.updateOne({id:"fireball"}, {$set:{power:30}})'
```

В PowerShell удобнее открыть интерактивно `docker compose exec mongo mongosh elemental_tactics`, затем выполнить `db.skills.updateOne({id: 'fireball'}, {$set: {power: 30}})`.

Агрегированный `/api/content` кэшируется на 30 секунд. При старте боя, создании персонажа и изучении навыка сервер читает свежие данные MongoDB, обходя кэш. Для немедленного обновления каталога можно удалить ключ `game:cache:content:v1` в Redis (с учётом `REDIS_NAMESPACE`). Изменения контента фиксируются при старте боя; активные инстансы сохраняют свои снимки. Начальные характеристики применяются к новым персонажам, текущие требования изучения — к новым покупкам навыков. Seed использует `$setOnInsert` и не перезаписывает существующие правки; обновление добавляет только отсутствующие поля и документы. Контент проверяется Zod-схемой: отрицательные стоимости, отсутствующие противники волн, неизвестные зависимости и циклы в дереве запрещены. Нужен доступный всем бесплатный базовый атакующий навык. Начальные данные находятся в `packages/core/src/content.ts`.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET / POST | `/api/characters` | Список / создание `{name, templateId?}`; без типа создаётся Странник |
| POST | `/api/characters/:id/skills` | Изучение навыка `{skillId}` |
| GET | `/api/content` | Валидированный каталог MongoDB, кэш до 30 секунд |
| GET | `/api/characters/:id` | Актуальный персонаж |
| GET | `/api/skills`, `/api/skills/:id` | Каталог / описание навыка |
| GET | `/api/items`, `/api/items/:id` | Каталог / описание предмета |
| GET | `/api/characters/:id/inventory` | Стэки с описаниями предметов; постоянный инвентарь персонажа |
| GET / POST | `/api/battles` | Список / создание `{name, characterId, kind, rule}` |
| GET | `/api/battles/:id` | Снимок инстанса |
| POST | `/api/battles/:id/join` | `{characterId, team: 0 или 1}` |
| POST | `/api/battles/:id/start` | `{characterId, version}` |
| POST | `/api/battles/:id/actions` | `{characterId, version, action}` |

Варианты `action`: `{type:'swap', from:{row,col}, to:{row,col}, targetId}`, `{type:'skill', skillId, targetId}`, `{type:'item', itemId}`, `{type:'end'}`. Координаты от 0 до 7. Основной транспорт — REST, включая все боевые команды. Socket.IO используется только при открытом бое: отправить `watch` с ID боя и дождаться acknowledgement, получать `battle` со снимками, отправить `unwatch` при выходе. Событие `rooms-changed` удалено; лобби загружается через REST раз в 5 секунд и по кнопке. Открытый бой сразу загружается через REST и сверяется каждые 5 секунд независимо от WS; после переподключения выполняются подписка и повторное чтение. Устаревшие версии снимков игнорируются.

## Redis и фоновые задачи

`pnpm infra` запускает PostgreSQL, MongoDB и Redis. Настройки: `REDIS_URL` и `REDIS_NAMESPACE` (по умолчанию `game`). Compose включает Redis AOF, volume `redis_data` и `maxmemory-policy=noeviction`; кэш и очередь используют разные префиксы. Не применять `FLUSHDB` для сброса кэша: это удалит и задачи.

Очередь BullMQ `battle-archive` сохраняет завершённые бои в MongoDB `battleArchives`. Запись outbox создаётся в той же PostgreSQL-транзакции, что результат и награды; диспетчер проверяет её каждую секунду. Обработка повторяется до 5 раз с экспоненциальной задержкой от 1 секунды. Повторная доставка безопасна благодаря ID задачи и уникальному ID архива. Последние 1000 успешных задач сохраняются; неуспешные остаются для диагностики и ручного повтора. Подробнее о восстановлении и ограничениях — [архитектура](docs/architecture.md#очереди-и-отказы).

Опыт, расход предметов и проверка хода выполняются синхронно в PostgreSQL, а не в очереди. Постоянный инвентарь пока доступен только для чтения; расход зелий остаётся изолированным внутри боя.

# При запущенном PostgreSQL: проверка миграций в отдельной временной базе.
pnpm --filter @game/server test:migrations
# При запущенных PostgreSQL, MongoDB и Redis: HTTP, WS, кэш, очередь, архив и shutdown.

Тесты ядра проверяют десять типов героев, доступность всех веток через развитие персонажа, применение всех 30 навыков в трёх режимах боя, совместимость старого контента, поле, каскады, энергию, три режима боя, NPC, волны, рост уровней, остаток XP, требования изучения, зависимости дерева и набор навыков бойца. Тесты сервисов используют транзакционную тестовую БД в памяти: проверяют одновременные команды, повторные награды, откат при ошибке сохранения и конкурентное изучение навыков. Отдельная команда `test:migrations` проверяет миграции на настоящем PostgreSQL: запуск с нуля, начальных героев, повторный запуск и сохранение изменённого прогресса. Адрес можно задать через `TEST_POSTGRES_URL`; используется отдельная временная база; пользователь PostgreSQL должен иметь право `CREATEDB` (в Docker оно уже есть). Обычные тесты не требуют PostgreSQL, MongoDB или Redis и дополнительно проверяют атомарность outbox и повторную доставку после отказа очереди. `test:infrastructure` создаёт отдельные временные PostgreSQL/MongoDB базы и уникальный Redis namespace, затем удаляет только их. Адреса можно задать через `TEST_POSTGRES_URL`, `TEST_MONGO_URL`, `TEST_REDIS_URL`. Проверка `pnpm check:architecture` запрещает обращения сервисов к драйверам, доступ к чужим репозиториям, сетевые запросы в UI-компонентах и циклические импорты.

Использованные официальные справочники: [NestJS gateways](https://docs.nestjs.com/websockets/gateways), [Kysely migrator](https://jsr.io/@kysely/kysely/doc/migration).
