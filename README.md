# Стихии — Tactical Match-3

Сетевой MVP: общее поле «три в ряд» и пошаговый бой. Node.js 22+, TypeScript, NestJS, React, PostgreSQL + Kysely, MongoDB, Redis, BullMQ, Socket.IO, pnpm workspaces.

Реализован [чат](docs/chat.md) модулем монолита: «Мир», общая лента «Личные» и
«Все», история PostgreSQL, REST и уведомления Socket.IO. Друзья/ЧС, группы,
показ вещей и обмен — следующие этапы. Вход пока через [выбор аккаунта без
пароля и своего персонажа](docs/identity.md).

Текущий проект — **базовая v1 до первого релиза**. Новую версию начинаем только
по явному указанию владельца проекта. REST API использует `/api/v1`.
До этого момента все изменения PostgreSQL входят в одну миграцию `init`;
старые варианты базы не обновляются цепочкой миграций, а пересоздаются.
`Battle.version` и ревизии в командах остаются счётчиками изменений состояния.

Правила структуры и взаимодействия: [архитектура](docs/architecture.md). Доменные правила: [бой и энергия](docs/combat.md), [боевое поле](docs/battlefield.md), [навыки](docs/skills.md), [предметы](docs/items.md), [инвентари](docs/inventory.md). Инструкции для дальнейших изменений: [AGENTS.md](AGENTS.md).

[Аудит игровых механик и хранения](docs/architecture/GAME_MECHANICS_AUDIT.md): исходная ревизия, сравнение с Perfect World и план развития. Реализованные после аудита уточнения допов описаны в [modifiers.md](docs/modifiers.md).

[Исследование формул Perfect World и адаптация к пошаговому бою](docs/combat-formulas.md):
проверенные исходники, производные характеристики, атака, броня, крит и
реализованный профиль формул базовой v1 и варианты дальнейшего развития.

Реализованы [цели участников, составные эффекты, бафы, дебафы и очищение](docs/skill-effects.md).
[Независимый рост параметров навыка](docs/skill-effects.md#независимый-рост-параметров-навыка): величина, вероятность и длительность имеют собственные настройки; отсутствие прироста сохраняет параметр неизменным. Стан реализован как автоматический пропуск полного собственного хода.
Периодические эффекты, щиты и заморозка поля — следующий этап. [Расчёт характеристик](docs/character.md)
уже реализован: сила, ловкость, интеллект, выносливость и удача; пять очков
для ручного распределения за уровень, производные и масштабирование экипировки.
Последовательность ходов и энергия сохраняют механику v1.

Реализован общий каталог модификаторов `modifierDefinitions` с булевыми
`allowSkill`, `allowWeapon`, `allowArmor`, `allowPotion`, `allowBuff`, `allowDebuff`,
`allowGem`. Крафт учитывает профессию при выборе ранга: ранг задаёт количество
допов, itemLevel — их величину. Цвет рамки
показывает качество. Рецепт может гарантировать ранг (пример — редкий меч за
12 руды). Экран крафта показывает профессии, опыт, шансы и выпавшие свойства.
Обычный ранг имеет 0 допов, мифический — 6. Один и тот же доп может выпасть несколько раз на одной вещи; у каждого места собственный бросок величины. [Правила](docs/item-progression.md).
Физическая мощь и [прибавка к физическому урону](docs/character.md#разделение-физической-мощи-и-прибавки-к-урону)
рассчитываются отдельно. Новые и тестовые герои получают 60 руды,
40 кожи и 40 травы из базового набора.

Реализованы [общие допы v1](docs/modifiers.md): опорные величины и профили
уровня предмета, взвешенный выбор с разрешёнными повторами, индивидуальные вероятности
применения и их необязательный рост от ранга навыка. Вещи сохраняют
уровень и снимки базы/допов; ранг определяет число допов.

## Запуск всего проекта

На новом компьютере установите Git и Docker с Compose (в Windows — запущенный Docker Desktop с Linux-контейнерами). Node.js и pnpm для этого способа не нужны:

```sh
git clone https://github.com/ShaevAndr/game.git
cd game
docker compose up -d --build
```

Откройте **http://localhost:8088**. Compose собирает и запускает frontend, backend, PostgreSQL, MongoDB и Redis. Для просмотра журналов используйте `docker compose logs -f`. Запуск в текущем терминале вместо фона: `docker compose up --build`.

Порт можно изменить через `GAME_WEB_PORT` в `.env`, затем выполнить `docker compose up -d`. Compose автоматически использует этот же порт для `WEB_ORIGIN` сервера. Если в Windows на `localhost:8080` появляется `Access Error: 404 -- Not Found`, проверьте конфликт со сторонним `ApplicationWebServer`: Windows и WSL могут отдавать разные страницы по IPv4 и IPv6. По умолчанию игра использует порт 8088.

Миграция PostgreSQL `init` и первоначальное наполнение MongoDB выполняются при старте сервера. `init` сразу добавляет десять готовых героев 10-го уровня — по два на каждую ветку, с изученными навыками и зельями. На новом устройстве не нужно создавать персонажей вручную. Данные сохраняются в Docker volumes. Остановить проект: `docker compose down`.

После изменения схемы `init` или несовместимого формата начальных данных
локальные тома можно пересоздать. Следующие команды удаляют весь локальный
прогресс PostgreSQL, каталоги/архивы MongoDB и состояние Redis этого Compose-проекта:

```sh
docker compose down --volumes
docker compose up -d --build
```

`down --volumes` запускается явно разработчиком; приложение не сбрасывает базы
автоматически. Для обычного обновления кода без изменения схемы из папки проекта:

```sh
git pull --ff-only
docker compose up -d --build
```

У каждого компьютера собственные базы и прогресс. Git переносит код и начальные данные миграций; для переноса накопленного прогресса нужны резервные копии баз.

### Разработка с обновлением кода

Для разработки установите также Node.js 22+:

```sh
corepack enable
pnpm install
pnpm infra
# Скопируйте .env.example в .env при необходимости изменить настройки.
pnpm dev
```

Клиент: **http://localhost:5173**, сервер: **http://localhost:3001/api/v1**. Vite и Nginx проксируют HTTP API и Socket.IO; клиент использует тот же origin. PostgreSQL и MongoDB обязательны: скрытой подмены на память нет. Redis используется для кэша и очередей; при временном отказе Redis чтение идёт из MongoDB, а архивирование боёв ожидает восстановления в outbox PostgreSQL.

В Windows при блокировке `pnpm.ps1` используйте `pnpm.cmd`. Если Corepack не может записать глобальные shims, можно установить их локально:

```powershell
New-Item -ItemType Directory -Force .corepack-bin
corepack enable --install-directory .corepack-bin
$env:COREPACK_HOME = Join-Path (Get-Location) '.corepack'
$env:PATH = "$(Join-Path (Get-Location) '.corepack-bin');$env:PATH"
pnpm.cmd install
pnpm.cmd dev
```

## Как попробовать

1. Выберите аккаунт без пароля: «Игрок 1» или «Игрок 2», либо создайте новый по имени. Откроется отдельная страница персонажей этого аккаунта. У готовых аккаунтов по пять героев 10-го уровня; у нового аккаунта можно создать своих. Выберите героя, чтобы войти в игру. Кнопки «Персонажи» и «Сменить аккаунт» возвращают к соответствующему выбору. Сессия хранится отдельно для каждой вкладки и восстанавливает выбранного героя при перезагрузке.
2. Для одиночной игры выберите **«Бой с ботом»**, создайте комнату и нажмите «Начать бой». Бот получает характеристики и изученные навыки вашего героя и ходит автоматически, включая лечение при низком здоровье. Можно также выбрать подземелье: три волны противников.
3. Для сетевой проверки создайте дуэль или командную комнату, скопируйте приглашение и откройте во второй вкладке/браузере. Выберите аккаунт и **другого** принадлежащего ему персонажа, вступите в другую команду, начните бой.
4. Выберите противника нажатием на карточку. Затем нажмите две соседние по стороне фишки. Обмен разрешён и без линии: позиции сохраняются, ход заканчивается без энергии, защиты и выбора навыка. Несоседние клетки и неверные координаты не тратят ход.
5. При создании комнаты можно задать строки и столбцы; набор типов фиксирован, по умолчанию поле 8 × 8 с шестью типами: четыре стихии, физическая сила и защита.
6. После анимации прямого сокращения выберите навык типа прямого совпадения в модальном окне. В нём также выбирается цель атаки или лечения. Другие типы навыков скрыты; нехватка энергии или перезарядка делает подходящий навык неактивным. Можно сохранить энергию и завершить ход. Прямые сокращения и каскады показываются отдельно. Если после сокращений нет обмена с совпадением, поле автоматически обновляется с теми же настройками.

Для игры с другого устройства откройте `http://IP-компьютера:8088` (или порт из `GAME_WEB_PORT`), разрешив этот порт в локальном firewall. В приглашении используйте доступный другим устройствам адрес вместо `localhost`.

Каталог v1 обновлён: начальные атаки стоят 3 энергии, добавлены четыре
контрольных навыка (три с уроном), массовая атака и групповое лечение.
[Числа и роли навыков](docs/skills.md#стартовая-настройка-каталога-v1).
Зелья используют общий исполнитель эффектов: 35 HP, 60 HP либо очищение
двух дебафов с лечением 15 HP. Состав фиксируется в экземпляре при крафте/выдаче
и переносится в боевой снимок; правка каталога не меняет старую бутылку.
Единственная `init` создаёт и колонку снимков эффектов; обновление базовой
установки выполняется явным пересозданием томов.

После выбора героя кнопка **«Чат»** открывает окно на любом игровом экране.
Вкладка задаёт просмотр, селектор «Отправить» — мир или конкретного игрока.
Нажмите имя автора и «Личное сообщение», чтобы выбрать адресата; все личные
сообщения остаются одной лентой. Черновик сохраняется при навигации и смене
своего героя, выход из аккаунта очищает окно.

## Правила MVP

В новых боях действует единый порядок: **перестановка → прямое сокращение и энергия → выбор навыка и цели → применение навыка → каскады и оставшаяся энергия → следующий участник**. Навык доступен только при прямом совпадении своего типа. Если подходящего изученного навыка нет, ход заканчивается автоматически. Видимые недоступные навыки не мешают завершить ход без применения.

Можно переставить соседние фишки без совпадения, потратив ход на подготовку поля. Такой обмен не вызывает каскады и перегенерацию, не даёт энергию или защиту и не позволяет применить навык. NPC предпочитает совпадения, но при их отсутствии тоже может выполнить обычный обмен. Интерфейс показывает только анимацию перестановки.

Обычные прямые и любые вторичные клетки дают по 1 **общей энергии умений**, максимум **30 на бойца**. Её запас показан под жизнями каждого бойца. Все умения тратят этот запас; «Удар» стоит **3 энергии**, без перезарядки. Вторичные клетки пополняют запас после навыка или пропуска; их энергия недоступна для оплаты текущего навыка. Каскадная энергия начисляется после списания стоимости, с повторным ограничением 30. Прямые клетки защиты дают **защиту до следующего собственного хода** по вычисленному `guardPerCell` (10 у базового героя без экипировки); вторичные дают общую энергию.

Перестановка фишек занимает 300 мс, каждое сокращение исчезает за **1 секунду**, затем оставшиеся фишки плавно падают вниз за 450 мс, а новые приходят сверху. Перед ходом бота отображается его активная карточка с паузой **1 секунда**. Во время анимации действия заблокированы. Сервер сохраняет контрольные состояния `playback` вместе с результатом, без ожидания внутри транзакции. После перезагрузки сразу восстанавливается актуальный результат; повторный REST/WS-снимок не повторяет анимацию.

Клетки сами не наносят урон. Сила навыка умножается на `1 + max(0, число прямых клеток − 3) × 0.3`: три клетки — ×1, четыре — ×1.3, пять — ×1.6. Вторичные клетки не усиливают навык. Коэффициент усиливает урон, лечение и величины модификаторов, сохраняя их длительность, шанс и цену. В новых боях урон зависит от физической/магической мощи, коэффициента ранга навыка, удачи и защиты соответствующего типа; лечение — от силы лечения и ограничено максимумом HP. [Формулы](docs/character.md). Прежние снимки без реестра используют `max(1, floor(сила текущего уровня × коэффициент + атака − защита цели − временная защита))` и прежний `balance.combat.defensePerTile`.

За ход можно применить один навык **или** зелье. Зелье доступно до обязательной перестановки. Перезарядка `2` блокирует следующие два собственных хода. Погибшие участники пропускаются. Командные бои поддерживают до 3×3 с чередованием команд; подземелье — до трёх игроков против одного противника в каждой волне. NPC соблюдает те же ограничения. Подробнее — [правила боя](docs/combat.md).

**Боевые состояния изолированы:** HP, энергия и перезарядки живут внутри конкретного боя; персонаж служит шаблоном. Собранная энергия не переносится в другие бои. Использованные зелья списываются из постоянного инвентаря и не восстанавливаются. Опыт, уровень, характеристики, очки навыков и изученные навыки сохраняются в PostgreSQL между боями. Постоянный инвентарь управляется на отдельном экране; оружие и броня дают бонусы при старте следующего боя. Изменение экипировки или уровня навыка не меняет уже активный бой.

## Уровни и дерево навыков

Откройте вкладку **«Навыки»** в верхнем меню или нажмите на очки навыков в карточке персонажа. Экран доступен напрямую по `/#skills`. Пять веток — огонь, вода, земля, воздух и физическая сила. В каждой ветке **шесть навыков и два типа героя**; рекомендуемые навыки героев и все зависимости показаны на карточках. У огня, воды, земли и воздуха есть отдельные пути атаки и лечения. Физическая ветка предлагает тяжёлые удары, быстрые атаки и «Второе дыхание» для лечения.

| Ветка | Герои и рекомендуемые навыки |
| --- | --- |
| Огонь | Пиромант — «Искра»; Адепт Феникса — «Тепло Феникса» |
| Вода | Хранитель прилива — «Источник»; Маг льда — «Ледяная игла» |
| Земля | Геомант — «Каменный осколок»; Друид — «Сок жизни» |
| Воздух | Заклинатель бури — «Дуновение»; Хранитель ветра — «Дыхание ветра» |
| Сила | Дуэлянт — «Выпад»; Ветеран — «Второе дыхание» |

Тип героя рекомендует направление развития, сохраняя возможность изучать все пять веток. Характеристики одинаковые. Новый персонаж любого типа, включая «Странника», получает уровень 1, 0 опыта, **2 свободных очка навыков**, **5 свободных очков характеристик** и только физический «Удар» первого уровня. Профильные навыки изучаются отдельно.

Для изучения сервер одновременно проверяет:

- достаточное количество очков навыков;
- все навыки из `learning.prerequisites`;
- минимальный уровень `learning.level`;
- минимальные характеристики `learning.stats`.

Уже изученный навык нельзя купить повторно. Его можно улучшить до **10-го уровня**: по умолчанию 1 ОН за улучшение и +2 силы за каждый уровень. Настройки хранятся в `skills.progression`. Свиток может выдать неизвестный навык уровня 1 без расхода очков; известный навык он не повышает. Стоимость изучения `learning.pointCost` отличается от затрат энергии на применение в бою. Очки списываются и навык сохраняется под блокировкой строки персонажа в одной транзакции: две вкладки не могут потратить одно и то же очко.

Награда за победу по умолчанию: **100 XP** за бой с ботом или дуэль, **140 XP** за командный бой, **240 XP** за полное прохождение подземелья. Каждый персонаж победившей команды получает полную награду, включая выбывших союзников; сдавшиеся участники награду не получают. Проигравшие и NPC опыта не получают; за отдельную волну награда не выдаётся. Завершённые до обновления бои не награждаются задним числом.

Порог следующего уровня: `100 + (текущий уровень − 1) × 50`. Остаток опыта сохраняется; за одну победу можно получить несколько уровней. Каждый уровень даёт **1 очко навыков** и **5 очков характеристик для ручного распределения**. HP, мощь и защиты меняются через распределённые параметры. Лимит энергии остаётся 30. Настройки находятся в MongoDB: `settings`, документ `id: balance`, поле `progression`.

Завершение боя, запись наград и развитие победителей сохраняются одной транзакцией. В таблице `battle_rewards` первичный ключ `(battle_id, character_id)` запрещает повторное начисление. Строки персонажей блокируются в одинаковом порядке, поэтому награды из разных боёв и изучение навыков не затирают друг друга.

При старте боя набор и уровни навыков, характеристики с бонусами экипировки обновляются из персонажей, после чего фиксируются в инстансе. Изучение в другом окне не меняет уже активный бой. Начальные настройки MongoDB добавляются при запуске сервера без перезаписи существующих правок. Изменение базовых форматов до релиза применяется через явное пересоздание локальных томов.

Откройте вкладку **«Крафт»** (`/#crafting`) и выберите известный рецепт. Появятся ячейки необходимых предметов: сколько нужно, сколько есть в рюкзаке и чего не хватает. Ингредиенты подставляются автоматически; «Создать» доступно, когда их достаточно. После крафта количества обновляются, выбранный рецепт остаётся открытым. Базовые рецепты (меч, броня, зелье и меч фиксированного редкого ранга) известны всем; у каждого героя есть стартовый набор материалов, а `init` создаёт готовых героев вместе с их стартовым имуществом. В отдельном режиме **«Эксперимент»** можно вручную выбрать количества: известное совпадение предлагает обычный рецепт, иначе сервер ищет случайный подходящий рецепт каталога; при успехе создаётся предмет, при неудаче материалы возвращаются или пропадают по настройкам баланса. Списание материалов и создание предметов сохраняются одной транзакцией с квитанцией `operationId`; повтор запроса не дублирует крафт и не перебрасывает случайность. Полная спецификация рангов, заточки, ячеек и профессий — в [развитии предметов](docs/item-progression.md).

## Бафы и дебафы

Во вкладке **«Навыки»** доступны семь новых умений: **Боевой клич**, **Ослабление**, **Уязвимость к огню**, **Очищение**, **Каменная кожа**, **Магическая концентрация** и **Рассекающий удар**. Они изучаются за обычные очки; рассекающий удар — со 2-го уровня, остальные — с 1-го. При запуске сервер добавляет определения в MongoDB, сохраняя пользовательские изменения.

Применение требует прямого совпадения типа навыка, энергии и готовой перезарядки. Для каждого умения сервер предлагает допустимые цели и показывает величину и срок эффекта. Баф действует сразу, но ход наложения не расходуется: два хода означают следующие два собственных хода получателя. Под бойцами отображаются раскрываемые значки с источником, изменением параметра, сроком, стэками и возможностью снятия. Очищение снимает один снимаемый дебаф; без подходящего дебафа энергия всё равно расходуется.

Сроки и эффекты сохраняются вместе с боем и восстанавливаются через REST после перезагрузки. Постоянные характеристики и вещи не меняются. Повторное наложение, истечение, очищение и NPC работают через один движок. Старые активные бои сохраняют прежние правила; новые эффекты доступны в новых боях. [Подробные правила и формат контента](docs/skill-effects.md).

## Характеристики персонажа

Пять первичных — **сила, ловкость, интеллект, выносливость, удача**. Старт: по 10. Каждый новый уровень даёт **5 очков для ручного распределения** во вкладке **«Экипировка»**. Отдельная таблица показывает базу, вклад экипировки, временных эффектов и итог: максимум HP, физическую/магическую мощь, лечение, пять защит и крит. Общий лимит энергии остаётся 30.

Оружие усиливается вместе с героем: `мощь тела + мощь оружия + их произведение / 20`. Поэтому полезны и развитие параметров, и улучшение оружия. В новых боях урон зависит от физической или магической мощи, защита выбирается по типу атаки, удача даёт крит. Герои v1 получают `5 + 5 × (уровень − 1)` очков характеристик; распределённые очки сохраняются. Каждый активный бой использует собственный снимок контента.

Реестр хранится в MongoDB `statDefinitions`; формулы и коэффициенты — данные. Действующие бафы/дебафы из навыков пересчитывают эти параметры и учитывают сроки по собственным ходам получателя. Подробные формулы и порядок пересчёта: [характеристики](docs/character.md).

## Предметы и инвентари

Во вкладке **«Экипировка»** (`/#equipment`) выберите слот персонажа и подходящую вещь из рюкзака. Вне активного боя можно надеть, заменить или снять предмет; бонусы и свободные места обновляются после действия. Замена возвращает прежнюю вещь в рюкзак, при полном рюкзаке снятие отключено с пояснением. Пока персонаж участвует хотя бы в одном активном бою, надевание, замена и снятие запрещены: кнопки показывают причину, сервер отклоняет прямую команду с 409. После окончания всех боёв действия снова доступны. Снаряжение сохраняется на сервере и фиксируется при старте боя. На телефонах все разделы доступны в прокручиваемой верхней навигации.

Откройте вкладку **«Инвентарь»** (`/#inventory`). Реализованы группы «Оружие», «Экипировка», «Зелья», «Ресурсы» и «Свитки». Группы хранятся в MongoDB `itemGroups`; новую группу с существующими действиями можно добавить без изменения кода.

Инвентарь устроен как в классических RPG: слоты надетых вещей вокруг силуэта героя и сетка рюкзака на 50 мест. Надетые вещи не занимают ячейки рюкзака. Нажмите на предмет для просмотра свойств; кнопка или двойной щелчок надевает/снимает вещь. Надевание в занятый слот автоматически возвращает прежнюю вещь в рюкзак; снятие при полном рюкзаке запрещено. Доступны поиск, фильтры, сортировка, разделение и объединение стэков, передача другому герою, чтение свитков и удаление. Создавать новые инвентари на экране не нужно. Предметы из старых контейнеров доступны в разделе «Другие сохранённые предметы». Зелья используются на экране боя; выдача новых предметов и навыков остаётся серверной операцией.

Личный рюкзак привязан к выбранному персонажу (`ownerId = Character.id`). Новый герой получает рюкзак, меч, броню, руду, свиток и зелья сразу при создании: персонаж и его имущество сохраняются одной транзакцией, ошибка откатывает всё. Перенос предметов новому герою доступен без предварительного открытия его инвентаря. Готовые герои и их канонические инвентари создаются вместе в `init`. Все команды изменения инвентаря требуют `operationId`; повтор запроса не дублирует эффект. Подробные REST-команды и ограничения — в [документе инвентаря](docs/inventory.md). Крафт, профессии, ранги и случайные допы реализованы; заточка, ячейки и остальное развитие предметов спроектированы в [item-progression.md](docs/item-progression.md). Предложения по ключам, квестовым предметам, трофеям, ремонту и зачарованию — в [документе предметов](docs/items.md).

## Готовые персонажи и миграции

Единственная миграция [init.ts](apps/server/src/infrastructure/database/migrations/init.ts)
создаёт всю актуальную схему v1, два аккаунта и десять героев 10-го уровня из
[demo-characters.json](apps/server/src/infrastructure/database/seeds/demo-characters.json).
У каждого героя изучены навыки своей ветки вместе с «Ударом» и профильными
эффектами в пределах нового бюджета, доступны 50 очков характеристик и стартовые предметы. Канонические
экземпляры сразу находятся в основном рюкзаке. Новые герои из интерфейса
начинают с уровня 1.

Kysely хранит единственную запись `init`. Повторный запуск сервера не повторяет
начальное наполнение и сохраняет прогресс; для изменившейся схемы используется
явный сброс томов по инструкции выше. До объявления следующей версии новые
миграции и преобразования прошлых форматов разработки не добавляются.
Бой с ботом не требует второго персонажа; NPC не получает опыт.

## Архитектура

```text
apps/server/src/
  modules/      домены: identity, characters, skills, items, inventory, battles,
                rewards, battle-history, content, battlefield
    <domain>/
      http/          REST-контроллеры и WS gateway
      application/   сценарии и бизнес-сервисы
      ports/         заменяемые контракты хранения и интеграций
      repositories/  PostgreSQL/MongoDB-адаптеры
      *.module.ts    только сборка зависимостей NestJS
  infrastructure/    подключения к PostgreSQL, MongoDB, Redis, BullMQ; миграции
  shared/            контракты транзакций, кэша, очереди; HTTP-фильтры
apps/web/src/
  app/          сборка приложения, навигация и общие действия
  features/     characters, skills, items, inventory, equipment, crafting, content, arena, battles, battlefield
    <feature>/  api/ (REST), model/ (хуки), components/ (представление)
  shared/       HTTP-клиент и общие UI-примитивы
packages/core/  чистые типы, Zod-схемы, модуль battlefield, движок боя и правила развития
scripts/        автоматическая проверка границ архитектуры
docs/          архитектурные правила и потоки данных
deploy/        Nginx для Docker
```

Самостоятельный модуль поля: [контракт и примеры](docs/battlefield.md). Он принимает квадратный/прямоугольный размер и массив типов; ход возвращает обновлённую матрицу, `direct`, `generated`, `total` и этапы сокращений.

Сервер — единственный источник состояния. Команды проверяют текущего участника, фазу, ресурсы, цели и версию. Изменение инстанса выполняется в транзакции PostgreSQL с `SELECT … FOR UPDATE`; устаревшая версия возвращает HTTP 409. После коммита сервер отправляет снимок в Socket.IO-комнату. Клиент переподписывается и перечитывает снимок после переподключения. При недопустимом действии транзакция откатывается, включая действия NPC.

В JSONB инстанса сохраняются поле, его размер/набор типов, отчёты `boardMoves` с координатами удалений и матрицами каскадов, контрольные состояния `playback`, участники с характеристиками, HP, энергия, инвентарь, навыки, перезарядки, очередь, фаза, режим, волна, журнал и **снимок контента**. Активные бои переживают перезапуск сервера. PostgreSQL также хранит версии и историю миграций Kysely.

Текущая конфигурация рассчитана на **один экземпляр NestJS** с фоновыми обработчиками в том же процессе. Redis для очередей и кэша сам по себе не масштабирует WS. При горизонтальном масштабировании нужен общий Socket.IO adapter (например Redis) для доставки событий между процессами. Ход игрока ограничен 30 секундами и автоматически завершается сервером.
Автоматического поражения при отключении и подбора соперников в MVP нет.

## Изменение контента без изменения кода

База MongoDB: `elemental_tactics`.

| Коллекция | Что хранится |
| --- | --- |
| `skills` | Стихия, стоимость энергии, сила, эффект, перезарядка; `progression`: 10 уровней, цена улучшения и прирост силы; `learning`: цена изучения, уровень, зависимости, характеристики и признак стартового навыка |
| `statDefinitions` | Пять первичных и реестр производных: формулы, границы, единицы, подписи |
| `items` | Определения: группа, лимит стэка, лечение, слот/бонусы экипировки или навык свитка |
| `itemGroups` | Расширяемые группы и поддержанные действия |
| `enemies` | Характеристики и набор навыков NPC |
| `characterTemplates` | Типы героев: имя, описание, ветка и `skillId` начального навыка первого уровня; его требования должны быть доступны новому персонажу |
| `settings` (`id: balance`) | Начальные характеристики, предметы, `combat`: версия, лимит 30, энергия за клетку 1, коэффициент защиты; размер команды, волны; `progression`: награды XP, пороги уровней, очки и прирост характеристик |

Например, изменить силу огненного шара:

```sh
docker compose exec mongo mongosh elemental_tactics --eval 'db.skills.updateOne({id:"fireball"}, {$set:{power:30}})'
```

В PowerShell удобнее открыть интерактивно `docker compose exec mongo mongosh elemental_tactics`, затем выполнить `db.skills.updateOne({id: 'fireball'}, {$set: {power: 30}})`.

Агрегированный `/api/v1/content` кэшируется на 30 секунд. При старте боя, создании персонажа и изучении навыка сервер читает свежие данные MongoDB, обходя кэш. Для немедленного обновления каталога можно удалить ключ `game:cache:content:v1` в Redis (с учётом `REDIS_NAMESPACE`). Изменения контента фиксируются при старте боя; активные инстансы сохраняют свои снимки. Начальные характеристики применяются к новым персонажам, текущие требования изучения — к новым покупкам навыков. Seed использует `$setOnInsert` и сохраняет настроенные записи при обычном перезапуске. При несовместимом изменении базовой v1 каталоги пересоздаются вместе с локальными томами. Контент проверяется Zod-схемой: отрицательные стоимости, отсутствующие противники волн, неизвестные зависимости и циклы в дереве запрещены. Нужен один стартовый физический атакующий навык без требований и перезарядки со стоимостью до 3; цены навыков — от 1 до 30 энергии. Начальные данные находятся в `packages/core/src/content.ts`.

Боевой Socket.IO используется при открытом бое: отправить `watch` с ID боя и дождаться acknowledgement, получать `battle` со снимками, отправить `unwatch` при выходе. Событие `rooms-changed` удалено; лобби загружается через REST раз в 5 секунд и по кнопке. Открытый бой сразу загружается через REST и сверяется каждые 5 секунд независимо от WS; после переподключения выполняются подписка и повторное чтение. Устаревшие версии снимков игнорируются.

Чат использует отдельный namespace `/chat` на игровых экранах: `subscribe`
с `auth.token`, acknowledgement, затем уведомления `message.created` с ID и
каналом. Текст и история читаются через REST; личное доступно только двум
аккаунтам. REST-сверка каждые 5 секунд восстанавливает пропущенные сообщения
при отказе WS. Повтор отправки с тем же `operationId` возвращает тот же результат;
другое тело — 409. Автоматическая очистка истории пока отключена.
`test:infrastructure` проверяет также приватность чата, откаты, повторы, лимит,
офлайн-доставку через REST, отказ push и сохранность после рестарта сервера.

## Redis и фоновые задачи

`pnpm infra` запускает PostgreSQL, MongoDB и Redis. Настройки: `REDIS_URL` и `REDIS_NAMESPACE` (по умолчанию `game`). Compose включает Redis AOF, volume `redis_data` и `maxmemory-policy=noeviction`; кэш и очередь используют разные префиксы. Не применять `FLUSHDB` для сброса кэша: это удалит и задачи.

Очередь BullMQ `battle-archive` сохраняет завершённые бои в MongoDB `battleArchives`. Запись outbox создаётся в той же PostgreSQL-транзакции, что результат и награды; диспетчер проверяет её каждую секунду. Обработка повторяется до 5 раз с экспоненциальной задержкой от 1 секунды. Повторная доставка безопасна благодаря ID задачи и уникальному ID архива. Последние 1000 успешных задач сохраняются; неуспешные остаются для диагностики и ручного повтора. Подробнее о восстановлении и ограничениях — [архитектура](docs/architecture.md#очереди-и-отказы).

Опыт, расход предметов и проверка хода выполняются синхронно в PostgreSQL, а не в очереди. Постоянные переносы, экипировка и свитки сохраняются транзакционно: сервис записывает новое состояние, возвращённое чистым ядром, и обновляет проекции персонажа вместе с квитанцией операции. Применение зелья должно списывать каноническую бутылку через `InventoryService`
в той же транзакции, что и изменение боя. Между боями зелья не восстанавливаются.

## Проверка

```sh
pnpm check
# Или отдельно: pnpm check:architecture, pnpm typecheck, pnpm test, pnpm build
# При запущенном PostgreSQL: проверка единственной init в отдельной временной базе.
pnpm --filter @game/server test:migrations
# При запущенных PostgreSQL, MongoDB и Redis: HTTP, WS, кэш, очередь, архив и shutdown.
pnpm --filter @game/server test:infrastructure
```

Тесты ядра проверяют 30 базовых навыков и 13 составных навыков в новой механике: прямые типы, видимость, недоступность, списание энергии перед каскадами, отложенное начисление, усиление от прямых клеток и восстановление незавершённого хода, лимит 30, временную защиту и её истечение, NPC и зелья. Дополнительно покрыты единые правила v1, поле, каскады, десять шаблонов, рост уровней, очки, зависимости и уровни навыков. Тесты сервисов используют транзакционную тестовую БД в памяти: проверяют одновременные команды, повторные награды, откат при ошибке сохранения и конкурентное изучение навыков. Отдельная команда `test:migrations` проверяет init на настоящем PostgreSQL: полную схему, ограничения, начальных героев, повторный запуск и сохранение прогресса. Адрес можно задать через `TEST_POSTGRES_URL`; используется отдельная временная база; пользователь PostgreSQL должен иметь право `CREATEDB` (в Docker оно уже есть). Обычные тесты не требуют PostgreSQL, MongoDB или Redis и дополнительно проверяют атомарность outbox и повторную доставку после отказа очереди. `test:infrastructure` создаёт отдельные временные PostgreSQL/MongoDB базы и уникальный Redis namespace, затем удаляет только их. Адреса можно задать через `TEST_POSTGRES_URL`, `TEST_MONGO_URL`, `TEST_REDIS_URL`. Проверка `pnpm check:architecture` запрещает обращения сервисов к драйверам, доступ к чужим репозиториям, сетевые запросы в UI-компонентах и циклические импорты.

Использованные официальные справочники: [NestJS gateways](https://docs.nestjs.com/websockets/gateways), [Kysely migrator](https://jsr.io/@kysely/kysely/doc/migration).


## Таймер, завершение боя и боевой пояс

Первую команду сервер должен выбирать случайно с вероятностью 1/2. Неравные
составы разрешены; мини-игра жеребьёвки пока не добавлена. Если первым выбран
бот, он должен выполнить ход автоматически. Один герой может иметь только один
активный бой, но несколько ожидающих комнат.

Ход по умолчанию длится **30 секунд**, включая выбор навыка. Перестановка и
зелье не продлевают срок. По истечении времени сервер должен пропустить ход до
перестановки либо завершить выбор без навыка с сохранёнными каскадами. Обработка
работает без браузера/WS и после перезапуска. Кнопка **«Закончить бой»** означает
подтверждённую сдачу выбранного персонажа; союзники могут продолжать. Поражение
последнего живого участника завершает бой и освобождает экипировку.

В **«Арсенале»** постоянно видны изученные умения, цена и перезарядка.
**«Посмотреть персонажа»** открывает характеристики, экипировку, рюкзак, пояс,
бафы и дебафы любого участника. Просмотр не останавливает таймер.
Показываются характеристики навыков до защиты и крита, без прогноза потери HP.

В пояс при старте попадает не более **10 имеющихся зелий суммарно**, без
бесплатной выдачи. Остальные остаются в рюкзаке. Каждое применение навсегда
списывает одну конкретную бутылку в общей транзакции команды; повтор команды
и ошибка сохранения не должны списывать лишнее. Новые бутылки не пополняют
текущий пояс. Перемещение/удаление/разделение/объединение зелий активного
участника запрещены; после боя доступны оставшиеся запасы. Подробности:
[бой](docs/combat.md), [предметы](docs/items.md#боевой-пояс),
[инвентарь](docs/inventory.md#постоянный-расход-зелий-в-бою).

Свежие каталоги и `init` описывают актуальную базовую v1. Существующие MongoDB
настройки сохраняются при перезапуске через `$setOnInsert`; новые стартовые
бюджеты — 2 очка навыков и 5 очков характеристик, каждый следующий уровень —
1 очко навыков и 5 очков характеристик. Для проверки полностью нового базового
состояния используются новые локальные тома по инструкции запуска; автоматический
сброс или преобразование уже распределённых очков не выполняется.


## Аккаунты без пароля

Текущий вход: **аккаунт → его персонаж → игра**. Список аккаунтов и создание
по имени публичны; остальные REST-запросы требуют серверный Bearer-токен.
`GET /characters` возвращает своих героев, создание назначает владельца из
сессии. Сессия действует 7 суток, в PostgreSQL хранится только SHA-256 токена.
Выбор другого аккаунта создаёт сессию без выбранного героя. Текущий режим
позволяет выбрать любой аккаунт без пароля; полноценное подтверждение личности
отложено по явному решению пользователя. Подробности API и UI — [identity.md](docs/identity.md).

Новые таблицы `accounts`, `account_sessions` и обязательная связь героя
`characters.account_id` добавлены в единственную `init`. Для существующей
локальной установки нужно пересоздать тома по инструкции запуска; автоматического
сброса данных или переназначения старых персонажей не выполняется.
